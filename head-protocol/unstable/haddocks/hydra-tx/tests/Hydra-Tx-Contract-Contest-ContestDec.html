Healthy contest with the ContestUsed redeemer: the contesting snapshot is one version behind the head because its decommit was already paid out, so the head holds Snapshot only and the stored commitment must be the snapshot's $sel:appliedAccumulator:Snapshot.

data ContestUsedMutation Source #

Constructors

ContestUsedAlterSignature

A wrong signature must be rejected by the ContestUsed signature check.

ContestUsedStoreSnapshotAccumulator

Stores the snapshot's own accumulator, which still counts the decommit the decrement already paid out. Both hashes are signed, so only the redeemer-kind selection rejects this (GHSA-f825-9gwc-h5xq).

ContestUsedAlterAccumulatorCommitment 
ContestUsedClaimUnused

Claiming ContestUnused for a snapshot one version behind fails the signature check at the current version.
